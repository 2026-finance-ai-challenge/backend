# 뉴스 수집·공개 API

이 문서는 개발 브랜치의 구현 계약이다. 운영 반영 여부와 실측 결과는 [파이프라인 점검 기록](PIPELINE_REINFORCEMENT_20260902.md)을 확인한다.

## 수집과 관련성

- 기본 주기는 이전 처리 완료 후 2분이다. 지원 75종목 중 가장 오래 확인한 8종목을 조회하며, 종목당 검색 결과는 최대 50건이다.
- 발행 후 36시간 이내, 미래 시각은 최대 15분 이내인 후보만 검사한다.
- 검색 요약은 기사 전문이 아니다. 제목·검색 요약은 각각 저장하지만, 전문은 언론사 공개 원문 영역에서 별도로 확보한다.
- 저장하려면 **제목과 추출한 실제 본문 양쪽에서 같은 종목이 확인되어야 한다.** 개별 종목 검색 결과에는 검색 대상 종목도 이 검증을 통과해야 한다.
- 기업명 경계와 긴 이름 우선 규칙으로 SK/ SK증권, 하이브/더하이브 같은 오연결을 막는다. 스포츠·정답 퀴즈, 추천 기사·투표 영역, 인코딩 손상이 있는 본문은 제외한다.
- 이 기준은 오수집 방지를 우선한다. 기업명이 제목에 없는 관련 산업 기사까지 모두 수집한다고 보장하지 않는다.
- 원문 추출은 구체적인 본문 선택자를 우선하고 광고·추천 링크·투표 영역을 제거한다. 인코딩은 HTTP·HTML 선언을 읽는다. 추출 실패를 검색 요약으로 대체하지 않는다.
- 원문 요청은 4개 병렬 슬롯을 사용한다. HTTP(S), 공개 IP, 허용 포트, 리디렉션을 검증하며 응답은 5MiB, 기사별 전체 요청은 45초로 제한한다. 수집 실행 5분 이후 새 원문 요청을 시작하지 않는다.

## 중복 판정

- 정규 URL 해시로 동일 URL 저장을 방지한다. 이미 저장된 provider ID는 원문 재요청 전에 제외한다.
- 최근 72시간, 최대 50,000개 후보를 색인한다. 저장 전 실제 본문을 검증한 뒤 비교한다.
- 전문이 있는 두 기사는 제목 유사도와 본문 해시·5단어 지문을 함께 확인한다. 검색 요약만 비슷한 후속 보도는 병합하지 않는다.
- 본문 5어절 지문 유사도 0.90 이상 또는 5어절 지문 0.70 이상·어휘 지문 0.85 이상을 함께 요구한다. 후자는 인용부호·기자 문구만 바꾼 보도자료 재전송을 위한 조건이다. 두 경우 모두 제목 유사도 0.55 이상, 발행 간격 36시간 이내여야 하며 제목 수치가 충돌하거나 관련 종목이 서로 다르면 병합하지 않는다.
- 한국식 수치 표기 2천500/2500 등은 같은 값으로 정규화한다. URL이 다르거나 동일 언론사가 재송고했어도 본문 중복을 검사한다.
- 다른 종목 연결을 검색어만으로 대표 기사에 추가하지 않는다. 기존 대표 기사와 새 기사에서 모두 검증한 종목만 재사용한다.
- 유사도는 의미 동일성의 증명이 아니다. 운영 감사의 유사 후보 수를 확정 중복 수로 보고하지 않는다.

## 분석·번역

- 수집은 원문 저장과 작업 등록까지 수행하며 OpenAI 응답을 기다리지 않는다.
- 감성·중요도·분류는 승인된 금융 NLP/K-FNSPID 모델을 사용한다. 한 실행에서 최대 10건, 동시 2건이며 30초 이후 새 작업을 점유하지 않는다.
- 영어 제목은 별도 작업으로 최대 5개씩 생성한다. 완료 후 2초 간격이며 미완료 제목은 EN/KR 목록 모두 공개하지 않는다.
- 본문과 양언어 What/Why/Impact는 최초 호버·상세 요청 때만 생성한다. 동일 원문의 EN/KR 요청은 하나의 공유 작업을 사용한다.
- 한 번의 gpt-5-nano 생성에서 한국어·영어 요약을 먼저 검증·저장하고 영어 본문을 이어서 완료한다. 전체 완료 전에도 summaryReady인 요약은 표시한다.
- 본문 캐시가 없다는 이유로 목록에서 기사를 숨기지 않는다. 공개 조건은 전문 확보, 검증된 영어 제목, 분류 READY다.

## API

| 경로 | 동작 |
| --- | --- |
| GET /api/v1/news | 종목·기간·감성·중요도·시장영향 필터 및 커서 목록 |
| GET /api/v1/news/{articleId} | 원문·제목·종목·요약·분석 메타데이터 |
| GET /api/v1/news/{articleId}/translation?locale=en 또는 ko | 선택 언어 요약과 공유 생성 상태 |
| POST /api/v1/news/{articleId}/translation?locale=en 또는 ko | 최초 생성 등록 또는 동일 캐시 재사용 |
| POST /api/v1/news/{articleId}/term-explanations | 서버가 기사 내 존재를 확인한 선택 문구의 금융 해설 |

목록 정렬은 LATEST, IMPORTANCE, MARKET_IMPACT다. 캐시 완료는 200, 생성 등록·진행은 202와 Retry-After로 구분한다. FAILED 상태가 202 응답에 포함될 수 있으므로 HTTP 상태만으로 생성 성공을 판단하지 않는다.

금융 용어 해설은 기사 문맥·허용 인용 ID를 검증하고 IP 해시별 요청을 제한한다. API 키와 원문 전문은 로그에 남기지 않는다.

## 운영 설정·정비

기본값: KMARKET_NEWS_COLLECTION_INTERVAL=2m, KMARKET_NAVER_NEWS_TARGET_BATCH_SIZE=8, KMARKET_NAVER_NEWS_DISPLAY=50, KMARKET_NEWS_MAX_ARTICLE_AGE=36h, KMARKET_NEWS_ANALYSIS_INTERVAL=5s.

기존 일괄 삭제형 maintenance는 기본 비활성이다. 원문 복구에는 scripts/export_news_audit_snapshot.py, 선택 실행 테스트 NewsSourceRepairPlanTests, scripts/apply_news_source_repair.py를 사용한다. 적용 전 계획 해시 검토·원본 백업·새 수집기 반영이 필요하다. 기본 실행은 읽기 전용이며 진행 중·변경된 기사는 건너뛴다. 잘못 추출된 본문을 복구하면 번역 캐시를 무효화하고 분류를 다시 대기시킨다.
