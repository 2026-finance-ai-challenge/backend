# 번역 캐시와 다국어 공시 RAG 설계

- 상태: 공시 제목 번역 메모리·백필 완료, 뉴스·본문 온디맨드 캐시는 구현 예정
- 기준일: 2026-08-24
- 기본 원문 언어: 한국어
- 기본 서비스 언어: 영어

이 문서는 뉴스·공시가 계속 누적되어도 생성형 AI 비용이 데이터 총량에 비례하지 않도록 하는 구현 기준이다. 한국어 원문은 사실의 기준으로 보존하고, 목록에 필요한 짧은 제목만 수집 직후 비동기로 번역한다. 뉴스 본문·AI Insight와 공시 본문은 실제 사용 요청이 있을 때 생성하고 전 사용자에게 재사용한다.

## 결정 사항

| 영역 | 생성 시점 | 저장·재사용 기준 |
| --- | --- | --- |
| 뉴스 제목 | 수집 직후 비동기 | 정규화 제목 SHA-256, `ko→en`, 번역 정책 버전 |
| 공시 제목 | 수집 직후 비동기 | 정규화 제목 SHA-256, `ko→en`, 번역 정책 버전 |
| 뉴스 본문·What/Why/Impact | 상세 또는 AI Insight 최초 요청 | 기사 원문 SHA-256, `ko→en`, 모델·프롬프트 버전 |
| 공시 본문 | 사용자가 요청한 섹션·표·문단 | 접수번호, 문서 버전, 섹션 ID, 원문 SHA-256, `ko→en` |
| 공시 RAG | 질문 시 | 한글 원문 검색, 영어 답변, 접수번호·문서 버전 격리 |

- 수집 트랜잭션은 OpenAI 응답을 기다리지 않는다. 원문 저장과 제목 번역 작업 등록만 같은 트랜잭션에서 멱등 처리한다.
- 본문 일괄 선번역 작업은 만들지 않는다. 기존 데이터 백필도 제목에만 적용한다.
- 한국어 원문, 구조화 표, 공시 인용 위치는 번역 성공 여부와 무관하게 유지한다.
- 번역이 없거나 실패했으면 한국어 원문과 `PENDING`, `FAILED`, `UNAVAILABLE` 상태를 명확히 반환한다. 빈 문자열이나 생성된 대체 내용을 사용하지 않는다.
- Naver Search API가 제공하는 데이터는 제목과 검색 요약이다. 합법적인 전문 공급 계약이 없는 기사를 `FULL_ARTICLE`로 표시하거나 전문 번역을 제공하지 않는다.

## 제목 번역 파이프라인

`원문 저장 → 제목 정규화·SHA-256 → 번역 메모리 조회 → 없으면 작업 등록 → 제한된 배치 번역 → 계약 검증 → 번역 메모리 저장 → 목록 응답에서 재사용`

제목 번역은 다음 순서를 적용한다.

1. 검수된 DART·금융 용어 사전의 완전 일치 번역을 우선 사용한다.
2. 기존 데이터 백필은 Codex가 직접 검수한 로컬 카탈로그만 사용하며 외부 LLM을 호출하지 않는다.
3. 신규 제목이 카탈로그에 없으면 `CATALOG_ENTRY_MISSING`으로 실패 종료하고 한국어 원문을 유지한다. 운영용 공급자 대체 경로가 별도 구현·승인되기 전에는 임의 번역을 만들지 않는다.
4. 입력 순서·개수·원문 해시가 응답과 일치하지 않으면 배치 전체를 저장하지 않는다.
5. 괄호, 정정 표시, 보고서 기간, 숫자, 회사명은 원문에 없는 값으로 바꾸거나 추가하지 않는다.
6. 동일한 정규화 제목은 뉴스·공시 도메인 안에서 하나의 번역을 공유한다.

2026-08-24 실측 기준 지원 종목 공시 234,071건의 고유 정규화 제목은 2,834개다. 직접 검수 카탈로그 백필 후 번역 메모리와 작업은 모두 `READY 2,834`이며 `PENDING`, `PROCESSING`, `FAILED`, 재시도 오류는 0건이다. 지원 공시 `234,071/234,071`이 영문 제목을 재사용한다. 백필의 외부 공급자 호출과 실제 비용은 0이다.

## 온디맨드 번역 계약

대상 API는 다음 형태로 구현한다. 세부 응답 스키마는 도메인 API 문서가 관리한다.

| Method | Path | 동작 |
| --- | --- | --- |
| `GET` | `/api/v1/news/{articleId}/translation` | 저장된 영어 본문·Insight 또는 현재 생성 상태 조회 |
| `POST` | `/api/v1/news/{articleId}/translation` | 기사 원문 버전의 영어 본문·Insight 생성 요청 또는 캐시 재사용 |
| `GET` | `/api/v1/disclosures/{receiptNumber}/sections/{sectionId}/translation` | 저장된 영어 섹션 번역 또는 현재 생성 상태 조회 |
| `POST` | `/api/v1/disclosures/{receiptNumber}/sections/{sectionId}/translation` | 현재 문서 버전의 섹션 번역 생성 요청 또는 캐시 재사용 |

- 캐시가 있으면 `200 OK`와 `READY`를 반환한다.
- 최초 요청 또는 진행 중인 동일 요청은 `202 Accepted`와 동일 작업 ID·`Retry-After`를 반환한다.
- 원문 제공 범위가 없으면 `409`와 `SOURCE_CONTENT_UNAVAILABLE`을 반환한다.
- 사용량 제한은 `429`, 회로 차단 또는 공급자 장애는 `503`으로 구분한다. 이미 검증된 캐시는 공급자 장애 중에도 제공한다.
- 응답에는 `sourceHash`, `targetLocale`, `status`, `modelId`, `promptVersion`, `generatedAt`을 포함한다.

## 저장·동시성 기준

- PostgreSQL 번역 메모리는 `contentKind + sourceHash + targetLocale + translationVersion`을 유일 키로 사용한다.
- 작업 상태는 `PENDING`, `PROCESSING`, `READY`, `FAILED`로 분리하고 시도 횟수, 다음 시도 시각, 마지막 오류 코드를 기록한다.
- Redis 분산 잠금은 원문을 포함하지 않은 해시 키를 사용하고 TTL을 둔다. Redis 잠금은 최적화이며 PostgreSQL 유일 제약이 최종 중복 방지 장치다.
- 오래된 `PROCESSING` 작업은 임대 만료 후 회수하고, 지수 백오프와 최대 시도 횟수를 적용한다.
- 원문이나 번역문을 로그에 남기지 않고 요청 ID, 원문 해시, 작업 ID, 모델·프롬프트 버전만 기록한다.
- 원문 해시나 번역 정책 버전이 바뀌면 새 캐시 항목을 만들고 이전 문서 버전의 번역은 해당 버전 조회에만 사용한다.

## 공시 RAG 언어 계약

공시 RAG는 번역된 공시를 검색 인덱스로 사용하지 않는다.

1. 한글 공시 원문을 구조 보존 청크로 분할하고 다국어 임베딩으로 색인한다.
2. 영어 질문을 같은 다국어 임베딩 모델로 변환해 해당 접수번호·문서 버전의 한글 청크만 검색한다.
3. 검색된 한글 근거와 영어 질문을 OpenAI에 전달해 영어 답변을 생성한다.
4. 모든 핵심 주장에 한글 원문의 문단·표 인용을 연결한다.
5. 검색 근거가 부족하거나 다른 공시 범위의 질문이면 추정하지 않고 영어로 거절한다.

번역 캐시 장애는 RAG 검색과 답변을 막지 않는다. 화면에서 영어 인용문이 필요하면 답변 완료 후 해당 인용 섹션의 온디맨드 번역을 별도로 요청한다.

## 비용·보안 운영 기준

- OpenAI 호출은 Backend가 인증한 AI 서비스에서만 수행하며 `store=false`를 사용한다.
- 뉴스·공시 텍스트는 명령이 아닌 신뢰할 수 없는 데이터로 경계 처리한다.
- 제목 배치 수, 분당 요청 수, 일일 토큰·비용 상한, 요청 타임아웃, 회로 차단을 배포 설정으로 관리한다.
- 캐시 적중률, 실제 생성 건수, 입력·출력 토큰, 실패율, 잠금 경합, 생성 지연을 메트릭으로 제공한다.
- 동일한 기사·공시·섹션의 동시 최초 요청이 하나의 공급자 호출만 발생시키는지 검증한다.
- 기존 제목 백필은 dry-run에서 카탈로그 누락 0건을 확인한 뒤에만 적용하며 공급자 호출 수와 예상·실제 비용 0을 기록한다.

## 구현 완료 조건

- 뉴스 수집 테스트에서 본문 번역 API가 호출되지 않는다.
- 동일 제목을 가진 여러 공시가 하나의 제목 번역 작업과 결과를 공유한다.
- 기존 지원 종목의 고유 제목 백필이 중단 후 재개 가능하고 본문 번역 작업을 만들지 않는다.
- 뉴스·공시 본문 최초 요청은 `202`, 완료 후 요청은 `200` 캐시 응답을 반환한다.
- 동시 요청 테스트에서 Redis 잠금 실패 여부와 관계없이 PostgreSQL에 번역 결과가 하나만 저장된다.
- 원문 변경, 모델·프롬프트 정책 변경, 실패·재시도·회로 차단 경로를 검증한다.
- 영문 질문이 한글 공시 근거를 검색하고 영어 답변·유효 인용을 반환하며 근거 부족 질문은 거절한다.
