# K-Market 개발·전달 절차

1. `AGENTS.md`, `docs/PRODUCT_SCOPE.md`, `docs/GIT_WORKFLOW.md`를 읽는다. 번역·뉴스·공시·RAG 작업이면 `docs/TRANSLATION_AND_RAG.md`도 읽는다.
2. Git 상태를 확인하고 최신 `dev` 기반 작업 브랜치를 사용한다.
3. 요청 범위만 구현하고 테스트·정적 분석·보안 검사를 실행한다.
4. 변경 내역, 검증 결과, 남은 위험을 사용자에게 제시한다.
5. 사용자 승인 전까지 커밋·푸시·PR·병합을 보류한다.
6. 승인 후 한글 명사형 제목으로 커밋한다. 작업 브랜치에서 `dev`로 병합한 PR에만 브랜치 삭제를 사용한다.
7. `dev`에서 `main`으로 병합하는 배포 PR에서는 `--delete-branch`를 절대 사용하지 않는다. 병합 후 원격 `dev`가 존재하는지 확인한다.

## 번역·RAG 변경 검증

- 뉴스·공시 수집 성공이 OpenAI 호출 성공에 의존하지 않게 한다.
- 제목은 정규화 SHA-256 기반 번역 메모리와 비동기 작업으로 선번역하고, 본문 일괄 선번역은 금지한다.
- 뉴스 본문·What/Why/Impact와 공시 섹션은 최초 사용 시 생성하고 동일 원문·언어·정책 버전 결과를 모든 사용자에게 재사용한다.
- Redis 잠금과 PostgreSQL 유일 제약을 함께 사용해 동시 최초 요청의 중복 공급자 호출·저장을 방지한다.
- 공시 RAG는 한글 원문을 검색하고 영어 답변만 생성하며 접수번호·문서 버전·인용 범위를 유지한다.
- Naver Search API의 제목·요약을 기사 전문으로 표시하지 않으며, 번역 결과도 검색 요약임을 유지한다.
- 기존 데이터 백필은 고유 제목만 대상으로 dry-run, 비용 상한, 체크포인트와 재시작 안전성을 검증한다.
- 번역 캐시 적중·미스, 생성 상태, 실패·재시도·회로 차단과 모델·프롬프트 버전을 테스트하고 문서화한다.
